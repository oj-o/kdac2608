# me, myself — 모바일 접근성 인터랙티브 미디어아트

## 목적

지체장애 관람자가 버튼이나 정밀한 손동작 없이, 카메라와 마이크만으로
자신의 움직임·소리·분위기를 하나의 디지털 정원으로 자라나게 하는 작품.
화면에는 조작 UI를 두지 않으며, 관람자는 작품을 "조작"하는 것이 아니라
관람자의 존재 자체가 작품의 일부가 된다.

## GitHub Pages에서 실행

1. GitHub에 새 repository 생성
2. `index.html`을 repository 최상위에 업로드
3. `Settings` → `Pages`
4. `Deploy from a branch`
5. `main` / `/ (root)` 선택
6. 배포된 `https://사용자명.github.io/저장소명/` 주소를 모바일 Chrome에서 열기
7. 최초 1회 카메라와 마이크 권한 허용 (별도의 안내 화면 없이 브라우저 기본 권한 요청만 사용)

GitHub Pages의 github.io 사이트는 HTTPS로 제공되므로 카메라/마이크 웹 API 사용에 필요한 보안 컨텍스트를 만족한다.

## 입력(input)과 출력(output) 구분

혼동하기 쉬운 부분이라 명확히 정리한다.

**입력 (센서에서 직접 읽는 값, `S` 객체)**
- `motion` — 카메라 프레임 간 픽셀 변화량 (몸짓/동작의 크기)
- `motionCentroid` — 프레임 변화가 몰린 위치 (움직임의 방향, 몸짓/표정 인식 실패 시 방향의 대체 수단)
- `volume` — 마이크 음량(RMS)
- `pitch` — 음성의 기본주파수를 0~1로 정규화한 값
- `headX/headY`, `smile/jaw/brow/eyeWide/blink`, `gazeX/gazeY` — MediaPipe Face Landmarker가 프레임마다 추출하는 얼굴/눈 관련 값
- `touch` — (선택) 화면에 손이 닿았을 때의 압력·이동량·유지시간을 종합한 값

**출력이 아니라 "복합 상태" (`C` 객체) — 그래픽과 사운드가 함께 참조하는 중간 계산값**
- `energy` — 위 입력들을 종합한 현재 에너지 수준 (0=고요 ~ 1=강렬). **감정 진단이 아니라 작품의 시각·음향 강도값**이다.
- `tension` — 최근 입력값들의 변동성(분산). 크고 불규칙하게 움직이면 올라간다.
- `impulse` — "순간 변화량". 절대적인 크기가 아니라 직전 값과의 차이를 감지한다. 아주 작은 동작이라도 갑자기 바뀌면 순간적으로 튀어 오르고, 이 값이 정원에 즉각적인 사건(새 가지, 새 꽃, 사운드 스파클)을 만든다.
- `dirAngle` — 정원이 자라나는 방향. 시선 → 머리 위치 → 프레임 움직임 중심 → (카메라가 없을 경우) 음성 피치 기반 추정, 순서로 우선순위를 둔다.

즉 실제 작품에 보이는 "분위기"는 하나의 정해진 라벨(예: 기쁨/슬픔)이 아니라
`energy`·`tension`·`impulse` 세 개의 연속값이 그래픽 밀도·속도·색상과
사운드의 화성/음색을 동시에 결정하는 구조다. 화면에는 이 수치들을 절대 표시하지 않는다.

## 신체 움직임이 제한적인 경우 — 대체 입력 경로

카메라와 마이크 중 하나만 있어도, 또는 몸/얼굴을 거의 움직이지 못해도 작품이 계속 반응하도록
여러 입력 경로를 병렬로 두고 있다.

| 가능한 신체 조건 | 실제로 반응하는 경로 |
|---|---|
| 손은 못 쓰지만 머리/상체는 움직일 수 있음 | 카메라 프레임 변화(`motion`) + 머리 위치(`headX/Y`)로 방향과 에너지 생성 |
| 머리/상체도 거의 못 움직이지만 눈은 움직일 수 있음 | MediaPipe의 시선 관련 블렌드셰이프(`eyeLookUp/Down/In/Out`)로 `gazeX/Y`를 계산 — 가장 적은 움직임으로 방향을 만들 수 있는 채널이라 방향 판단에서 가장 먼저 우선 적용됨 |
| 표정 근육 움직임이 제한적임 | 표정(`smile/jaw/brow`) 비중을 낮게 두고 `eyeWide`(눈 크게 뜸)·`blink`(깜빡임)까지 포함해 더 미세한 변화도 감지. 그래도 반응이 약하면 음성(음량/피치)이 같은 비중으로 에너지에 반영되므로 표정 없이도 작품이 자란다 |
| 얼굴/몸 움직임이 전혀 어렵고 목소리만 가능 | 카메라 자체가 없어도(`camOK=false`) 음량·피치만으로 에너지·방향·화성을 전부 만들어낼 수 있도록 fallback 로직이 분리되어 있음 — **음성만으로도 유사한 결과 생성이 가능** |
| 소근육(손가락)은 어느 정도 가능함 | 화면 터치는 필수 조작이 아닌 "선택적 보조 채널"로만 존재. 누른 시간·이동 거리·압력의 **정도**에 따라 그래픽 강도가 달라지며, 터치가 없어도 작품은 동일하게 작동한다 |

또한 아주 작은 움직임/소리도 화면에서 뚜렷하게 보이도록, 입력값을 그대로 쓰지 않고
저입력 구간을 크게 증폭하는 곡선(`boost()`, `CONFIG.sensitivityCurve`)을 거친 뒤 사용한다.
그리고 "현재 크기"뿐 아니라 "방금 얼마나 바뀌었는가"(`impulse`)를 별도로 감지하기 때문에,
움직임의 절대량이 작은 사람이라도 미세한 변화(눈썹을 살짝 움직이는 정도)만으로
정원에 즉시 눈에 띄는 사건(새 가지, 꽃, 짧은 스파클 사운드)이 일어난다.

## 시각 장애가 있는 경우 — 화면 밖 출력

그래픽/사운드는 시각·청각 중심 매체라 시각 장애 관람자에게는 그 자체로 전달되지 않는다.
이를 보완하기 위해 화면에는 보이지 않지만 스크린리더가 읽을 수 있는
`aria-live` 텍스트(`#srDesc`, `.sr-only`로 시각적으로는 숨김)를 추가했다.

- 약 6초 간격으로 정원의 현재 상태를 문장으로 갱신한다.
  예: "잔잔하게 흔들리는 정원이 가지를 뻗어가는 모습입니다.", "강렬하게 요동치는 정원이 무성하게 뻗어나간 모습입니다. 방금 하나의 꽃이 피었습니다."
- 수치(에너지 0.7 등)를 그대로 읽지 않고, 사람이 알아듣는 문장으로 변환한다.
- 사용자의 감정을 진단하는 문장("당신은 ~합니다")이 아니라 정원(작품)의 상태를 설명하는 문장이다.
- 화면에는 표시되지 않으므로 시각적 미니멀리즘 원칙과 충돌하지 않는다.

## 작품 변화 매핑

```text
동작 크기(motion, boost 적용) → 성장 속도, 앰비언트 입자 밀도
동작/시선/머리 위치의 방향    → 가지가 뻗어나가는 방향
음량(volume, boost 적용)      → 분기 빈도, 꽃(개화) 크기와 발생 확률, 사운드 에너지
피치(pitch)                   → 가지의 높이 편향, 가지 두께, 사운드 음높이·필터
표정(smile/jaw/brow/eyeWide)  → 에너지 기여도, 화성의 밝기
시선(gazeX/Y)                 → 방향(최우선), 에너지 기여도
터치(선택, touch)              → 에너지 기여도, 이동 시 가지 방향
변화량(impulse)                → 절대 크기와 무관하게, 순간적인 변화 자체가 새 가지/꽃/스파클 사운드를 즉시 발생
energy/tension 복합값          → TONAL_MAP 중 하나의 화성(calm/mid/bright/tense)을 연속적으로 보간해서 선택
```

## 접근성 원칙

- 작품의 핵심 조작으로 버튼을 사용하지 않는다.
- 사용자의 손 정밀 동작을 요구하지 않는다. 터치는 있어도 되고 없어도 되는 보조 채널이다.
- 움직임이 작은 경우에도 감도 증폭(boost 곡선)과 변화량(impulse) 감지로 뚜렷하게 반응한다.
- 카메라가 작동하지 않으면 마이크(음량·피치) 기반 경험으로 전환한다.
- 마이크가 작동하지 않으면 카메라(동작·시선·표정) 기반 경험으로 전환한다.
- 얼굴/음성/감정을 의료적·심리적으로 진단하지 않는다. `energy`/`tension`은 작품의 시청각 상태값일 뿐이다.
- 화면에는 수치, 상태 텍스트, 사용법 안내를 표시하지 않는다. 시각 장애인을 위한 설명은 화면 밖(스크린리더 전용)으로만 제공한다.

## 전시 설치 시 고려사항 (물리적 배리에이션)

코드가 아닌 실제 전시 공간 설계 시 참고할 접근성 가이드.

- **인식 위치의 다양화**: 관람자의 키/자세(휠체어 착석, 선 자세, 침대·리클라이너 이용 등)에 따라 카메라·마이크가 얼굴을 인식하기 좋은 높이가 달라진다. 거치대를 여러 높이로 준비하거나 상하 이동이 가능한 마운트를 사용한다.
- **휠체어 동선**: 카메라 인식 범위 앞에 휠체어가 진입·회전할 수 있는 최소 공간(권장 폭 150cm 이상, 문턱 없는 바닥)을 확보한다.
- **손잡이 설치**: 서 있는 자세 유지가 어려운 관람자를 위해 인식 구역 옆에 안정적으로 잡을 수 있는 봉/손잡이를 설치한다.
- **바닥 점자 표시**: 시각 장애 관람자가 카메라 인식 범위(정면 응시 위치)를 발로 확인할 수 있도록 점자블록 또는 촉지 유도블록으로 정위치를 표시한다. 화면 속 스크린리더 안내(`#srDesc`)와 함께, "지금 서 있는 위치가 인식 범위 안인지"를 물리적으로 알려주는 역할을 한다.
- 이 항목들은 전시 공간·예산에 따라 선택적으로 적용하는 설치 가이드이며 `index.html` 코드와는 독립적이다.

## 중요한 기술 조건

카메라와 마이크는 웹 브라우저의 `getUserMedia()`를 사용한다.
이 기능은 사용자 권한이 반드시 필요하다.

완전한 오프라인 `file://` 실행과 실제 카메라/마이크를 동시에 보장하는 방식이 아니라,
**GitHub Pages의 HTTPS 웹사이트에서 실행하는 전시용 구조**다.

표정 분석 모델은 MediaPipe Tasks Vision CDN과 Google Storage의 모델 파일을 불러오기 때문에 최초 접속 시 인터넷 연결이 필요하다.

음성 인식(말의 내용을 텍스트로 해석하는 기능)은 사용하지 않는다.
목소리는 오직 음량과 피치라는 물리적 특성으로만 해석되며, 말의 내용으로 감정을 판단하지 않는다.

```text

README.md
```

별도의 Node.js, Python, localhost 서버는 필요하지 않다.
